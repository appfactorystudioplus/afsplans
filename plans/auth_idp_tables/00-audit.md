## 0.3 What this does NOT touch

- `checkpoint_*` tables: they stay in the shared database on the `checkpoint` connection. The reason for that placement is sound (members and the Brain read them; Auth owns the schema, `AGENTS.md` §5).
- The `ext_*` tables (Delight-Auth; `ext_admin_users*` is the older, dead family): created by no migration, not part of this change.
- Members, Brain and Parse accounts: a different population (`account_close/03-database-schema.md:283` already says staff `admin_users` are "not touched" by account closure).

## 0.4 Why this matters beyond the login

1. The IDP panel cannot sign anyone in on any environment whose Auth database lacks the tables — which is the lab, and by the same migration, any freshly built environment.
2. A restore "works" because it fills the wrong copy, so nothing reports it.
3. The obvious repair (create the tables where the code reads them) makes the seeder's `admin` / `admin123` account real everywhere, so the forced password change (AF12) has to ship with it.
