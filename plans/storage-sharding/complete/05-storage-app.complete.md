Behaviour worth stating:

- **Hostname is the device.** `{N}.storage-device.{base_domain}` → N (strict parse) → hosted (from pulled config) →
  locally online (real mount point + marker naming N). Any failure is the *same* bare 404, byte for byte. With no
  config pulled, everything is a 404.
- **Directions cannot be swapped.** Members→device uses `X-Storage-*` and the members key; Brain↔device uses
  `X-Brain-*` and the server credential. The signed path differs, nonces are remembered, ±300 s skew, rotation
  accepts current + next key. An unconfigured surface refuses everything (an empty key never matches).
- **The device never trusts a path.** Every path is validated at grant and again at commit, and goes through
  `PathResolver`, which is rooted at one device and asserts `realpath()` containment. `.part` files are named by
  opaque ids. Directory removal never follows a symlink. There is no "run this path" operation.
- **Offsets are the `.part` length on disk.** A wrong-offset chunk is a 409 carrying the true offset; a short or long
  body is rolled back so a failed chunk never moves the offset; one writer per file via `flock`.
- **Commit is idempotent and crash-recoverable.** A repeated commit returns the same answer; a commit that died after
  `rename(2)` is recognised on retry (size + digest must match, so it never blesses a different file).
- **Tokens:** RS256 only (the algorithm is never read from the token), `kid`-selected public keys, `dev`/`ops`/`sub`/
  `sid`|`nid` checks, uniform `TOKEN_INVALID` except a true expiry. The app contains no signing code (a test asserts it).
- **Body is never rewritten:** `TrimStrings`, `ConvertEmptyStringsToNull` and `ValidatePostSize` are removed, so a JSON
  `rel_path` of `"a "` reaches the validator exactly as sent.

## Not verified

- **The 4 symlink-containment tests never ran.** They cover: a symlink planted after grant (commit), a symlinked file
  on download, a symlink in a tree being deleted, and the resolver's own containment. Run the suite on Linux (or
  Windows in Developer Mode) before trusting those defences. They are the point of the containment design.
- **No real mount.** `MountProbe` was faked; `StatMountProbe` (device-id differs from parent) was never run on a
  real mount. Same for `inodes_free` (`stat -f`, Linux only, returns null elsewhere), `fsync`, `flock`, and the
  write probe on a real XFS device.
- **No Brain.** The pull and report were exercised against `Http::fake`. Whether www's `brain.storage` middleware accepts
  a real request from this client is only established by both using the same signer (pinned by vectors), not by a call.
  That "a 302 is never followed" is set with `allow_redirects => false`; the fake cannot prove the option itself.
- **No web server.** CORS was tested in-process. `proxy_request_buffering off`, body limits, timeouts, wildcard TLS and
  passing the original `Host` through are deployment prerequisites (step 11), documented in the README.
- **No large upload.** Chunk sizes in tests are bytes-to-kilobytes; a 64 MiB chunk and a multi-GB file were not streamed.
- **`composer install` was never run for this app**, so `composer.json` and the `ext-intl` requirement are unexercised,
  and there is no `composer.lock`. The app was never started with `php artisan serve` or run from `public/index.php`.
- The real (non-`:memory:`) SQLite file with WAL was not exercised; the migration ran only in memory.

## Decisions to confirm

1. **Download tokens are not single-use.** The plan says single-use `jti` *and* resumable `Range` download; those
   conflict (resuming re-presents the token). The device does not record spent `jti`s; the 5-minute lifetime and the
   `dev`/`nid`/`rel` binding are the limits. Recorded as an open question in [06](../06-direct-upload-protocol.md) §3.
2. **RS256, not EdDSA,** for tokens — this PHP has OpenSSL but not libsodium. Members must mint RS256.
3. **A download token carries `bkt` and `rel`,** because the device has no node table. Added to 06 §3.
4. **The test RSA key pairs are committed** under `tests/fixtures/` and labelled test-only. If you would rather generate
   them per run, say so; it needs an `openssl.cnf`, which this machine's PHP lacks.
